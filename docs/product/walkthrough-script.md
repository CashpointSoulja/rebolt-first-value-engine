## 1. Set the boundary

**Action:** show the workbench title and notices.

**Say:** “This is First Value Engine, an independent concept by Ayo Ahmed, not affiliated with Rebolt. It is a synthetic-data GTM experiment workbench, not an aircraft operational tool or a real integration. Its typography uses a local Arial adaptation.”

**Verify:** the visible application matches these notices; no native-product or real-customer implication.

## 2. Ground the job without inventing product access

**Action:** point to the documented context only if that reference is present in the actual UI; otherwise explain it verbally.

**Say:** “The public growth role describes acquisition-to-activation experiments, cross-product onboarding and billing work, and measurement frameworks. Deidentified owner-reported entry attempts did not reach an authenticated workspace. Those reports are separate from official public-page research and do not establish a missing feature.”

**Say:** “The official pilot guide describes four-to-six-week assisted pilots. This seven-day synthetic measurement window is unrelated.”

## 3. Read the contract before a rate

**Action:** show the current dataset and settings.

**Say:** “The unit is a synthetic account. The default cohort is September 1 inclusive to October 11 exclusive, with an October 11, 2026 UTC cutoff and a seven-day elapsed window. These are fixed settings, not a moving current-date calculation.”

**Action:** read the actual displayed N, D, U, F, coverage and bounds. **Do not pre-script numeric sample results.**

**Say:** “D is all eligible time-mature accounts. Unknown outcome coverage stays inside D. A definitive rate is available only when U is zero. Pending, excluded and eligibility-unknown populations remain visible.”

**Verify:** population and segment/channel totals reconcile; median is labeled confirmed converters only.

## 4. Separate reached stages from verified value

**Action:** inspect stage observations and a segment/channel breakdown, including unknown.

**Say:** “These are observed reached-counts against the same mature denominator, not a guaranteed monotonic funnel. First use is not first value. Verified value needs a completed synthetic use-case result plus an approved evidence category. Those categories are not measured amounts or real customer outcomes.”

**Verify:** no adjacent-stage causal ratio, significance claim or retrospective reassignment.

## 5. Reject invalid input without corrupting the analysis

**Action:** record active dataset identity and settings, choose **Try an invalid synthetic example**, then **Validate draft**.

**Say:** “The draft exposes row/fatal diagnostics and row accounting. It cannot replace the last valid active dataset. A diagnostic candidate is not a committed analysis.”

**Verify:** import is rejected, identity/results/settings are unchanged, and the error is reachable and announced with sensible focus. Then correct the draft if needed. For a valid draft, validation alone does not commit: **Apply validated dataset** is a separate action.

**Action:** submit an invalid settings draft, such as end before start.

**Verify:** settings/results stay active at the prior valid values. Correct the draft before continuing. Do not narrate a pass if either invariant fails.

## 6. Demonstrate a zero denominator honestly

**Action:** if these controls are available, apply cohort `[2026-10-10T00:00:00Z, 2026-10-11T00:00:00Z)`, cutoff `2026-10-11T00:00:00Z`, window seven days, all segment/channel filters. Any included signup is too recent to be time-mature. If the interface differs, use an equivalent valid empty/immature synthetic fixture.

**Say:** “There is no eligible mature denominator here. That means not estimable, not zero-percent conversion.”

**Verify:** D=0, null/not-estimable fractional outputs, no fabricated median or bottleneck. Choose **Load synthetic sample** to restore the default settings and sample together.

## 7. Choose a hypothesis, not a predicted winner

**Action:** inspect one actual ranked proposal and its score inputs.

**Say:** “The priority score is impact times evidence confidence divided by effort, each on a one-to-three ordinal scale. Here are the stated inputs and rationale. It is a transparent planning heuristic, not expected uplift, causal proof, significance or ROI.”

**Verify:** action, audience, evidence, guardrails and success/stop criteria are visible or available before export.

## 8. Construct a URL; do not launch anything

**Action:** enter destination `https://example.org/learn?topic=sample#overview` and synthetic source/medium/campaign labels. Generate the string without opening it.

**Say:** “This adds encoded UTM parameters while preserving permitted query and fragment values. It constructs a URL locally; it does not launch a campaign or visit the destination.”

**Verify:** invalid/conflicting values produce errors; no request to the constructed destination occurs.

## 9. Export and read back the plan

**Action:** use generic owner `Growth owner`; review hypothesis, guardrails and success/stop criteria. Download the local JSON/CSV using the actual controls.

**Say:** “These are planning files. They carry aggregate and metric context, mature/unknown counts, score rationale and proposed next action. Their identifier represents aggregates and settings, not a unique raw dataset; row counts unavailable from the analysis contract are labeled unavailable. They do not contain imported account/event identifiers or demonstrate a completed experiment.”

**Verify:** independently inspect both exports for required context, safe CSV handling, identifier redaction and synthetic/non-affiliation notices. A visible download alone is not a passed readback check.

## 10. Close with limitations and accessibility evidence

**Action:** navigate a representative import/settings/export path by keyboard, show visible focus, and review the actual mobile layout if that review is authorized and available.

**Say:** “All inputs and results shown are synthetic. No real billing, operational system, campaign or authenticated Rebolt workspace is connected. Imported data is intended to remain local with no default persistence. Actual network/storage and accessibility checks are recorded separately; anything untested remains unverified.”
