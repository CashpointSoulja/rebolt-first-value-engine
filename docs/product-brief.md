# First Value Engine — research-stage brief

**Independent concept by Ayo Ahmed. No affiliation or endorsement by Rebolt.**

## Status and decision gate

Research only. No production UI may be built until this brief and brand evidence are committed **and** scoped product-use notes are supplied. This is not an approved PRD. Role ownership below is supplied project context, not an independently verified vacancy description.

## Proposed job

Help a person owning **acquisition, activation, billing/onboarding and growth experiments** turn a synthetic signup/event dataset into a transparent first-value diagnosis and a reproducible next experiment.

Proposed JTBD: “When a cohort signs up but its path to value is unclear, help me identify the observed bottleneck, define a measurable milestone and export a defensible experiment plan—without disguising incomplete data as poor conversion.”

## Product category and intended user

A **GTM experiment workbench**, not an aircraft operational tool. Proposed primary user: a growth/product operator. Aircraft-maintenance organizations are the current marketing context, not a mandate to model aircraft, findings or operational decisions.

This concept evaluates signup-to-value journeys. It does not generate Rebolt apps, recreate its operational platform or assert missing analytics/experimentation functionality. Published aviation capabilities include commercial and billing preparation; that is distinct from this workbench's hypothetical onboarding/payment funnel analysis.

## Official context — observed, not validated

The [current aviation page](https://www.rebolt.ai/aviation) describes “Agentic AI for Aircraft Maintenance,” with planning, engineering, hangar execution, materials, operational control and commercial/billing workflows. The [generic introduction](https://www.rebolt.ai/introducing-rebolt) describes a platform for operations across existing systems. The [pilot guide](https://www.rebolt.ai/pilot) recommends an accountable owner, use case, timeline and before/after evidence; it describes four-to-six-week pilots.

Those are published descriptions, not independent performance validation or confirmation of a new user's actual product journey. They motivate research questions, not claims about internal funnels or missing features.

## Candidate scope — all provisional

| Capability | Intended output | Honesty requirement |
|---|---|---|
| Synthetic CSV validation | Row-level issues and dataset accounting | No silent dropping of bad rows; no personal data |
| Cohort analysis | Explicit N/D/U counts, maturity and completeness | No immature-vs-mature comparison disguised as conversion |
| Milestone definition | Versioned proposed first-value event contract | Setup, first use and verified value are distinct |
| Segmentation | Signup-time segment breakdowns with unknowns | No causal channel claims or sparse-segment certainty |
| Experiment priority | Transparent input scores, evidence and ranking | A heuristic, never expected uplift or monetary ROI |
| UTM construction | Encoded, validated campaign URL | No campaign launch or third-party contact |
| Activation-plan export | Dataset/metric versions, hypothesis, owner, window, guardrails | A plan, not a completed action or integration |

Hypothesis H1: a clear first-value definition is more useful than treating signup as activation. H2: displaying incomplete/unknown evidence prevents false bottleneck conclusions. H3: explainable prioritization and export reduce ambiguity in the next experiment. None is established by public Rebolt evidence.

## Explicit exclusions

Real customer/business data; operational aircraft tooling or safety advice; live system write-backs; payment collection, checkout, subscription changes or revenue inference; real marketing campaigns; paid APIs; API keys; external contacts; applications; LinkedIn research; authenticated Rebolt inspection; invented native Rebolt screens; unsupported revenue, conversion, productivity or certification claims.

## Required scoped context before implementation

1. Actual product-use path: what was attempted and observed, using redacted/non-sensitive notes only.
2. Target user and unit: person, account or workspace; who owns the journey versus who receives value.
3. First-value action and evidence: what solved the user's job, prerequisites and genuinely observed friction.
4. Journey type: self-serve versus assisted pilot; onboarding stages; billing eligibility and payment evidence, if relevant.
5. Permitted synthetic event names, attributes, cohort timezone, observation cutoff and completeness assumptions.
6. Priority workflow to implement first and desired activation-plan export format.

Unresolved: no authoritative actual event taxonomy, trial/pricing rules, activation threshold or benchmark has been established. Do not fill these gaps with invented Rebolt facts.
